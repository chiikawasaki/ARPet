# WelshCorgi アニメーション修正レポート(2026/07/08)

## 不具合の内容

WelshCorgi の特定のアニメーションが再生されない。

- 例: `001_Ball_Catch+Jump` は再生されるが、`002_Ball_Jump`・`003_Ball_Jump+Catch` は再生されない
- 症状: Animator のステートは遷移している(ステート自体は動く)のに、犬のモデルが一切動かない
- 調査の結果、全323個のアニメーションFBXのうち **195個** が同じ理由で再生不能だった(Pat系・Sleep系・Disconnect系など多数)

## 原因

**FBX内の余分なラッパーノードによる、アニメーションカーブのバインドパス不一致。**

このプロジェクトのリグ設定は全FBXで Generic・Avatar無し(`animationType: 2`, `avatarSetup: 0`)。この構成では、Unity はアニメーションカーブを **Transform の相対パス文字列** で対象ボーンにバインドする。

インポート後のカーブパスを比較すると:

| ファイル | カーブパス |
|---|---|
| モデル (`Base/WelshCorgi.fbx`) の実階層 | `Root/Bip001/Bip001 Pelvis/...` |
| 001(正常) | `Root/Bip001/Bip001 Pelvis/...` ← 一致 ✅ |
| 002・003(不良) | `Corgi@Skin/Root/Bip001/Bip001 Pelvis/...` ← 先頭に `Corgi@Skin/` が余分 ❌ |

不良FBXはスケルトンの外側に `Corgi@Skin` というラッパーノードを1段持っており、モデル階層にはこのノードが存在しないため、**全カーブが1本もバインドされず「再生されているのに動かない」状態**になっていた。

ボーン名・ボーン構造自体(`Bip001 Pelvis` 以下)は正常ファイルと完全に同一。「ボーン構造が怪しい」という当初の仮説は半分正解で、正確にはボーンではなくその親のラッパーノードが原因だった。

補足:
- 不良FBXには `Feel_Bip001 ...` という重複ボーン群や `HeadPoint`/`PeePoint` 等のヘルパーノードも含まれるが、これらは存在しないボーンへのカーブとして無視されるだけで直接の原因ではない
- `Ani/002_Ball_Jump_Fixed.anim` という過去の修正の試みらしきファイルが存在したが、カーブが全て空で機能していなかった(不要なら削除してよい)

## 調査のアプローチ

1. **インポート設定の比較**: 正常/不良FBXの `.meta` を比較 → リグ設定は全て同一で差なし。設定起因ではないと判断
2. **FBXバイナリの解析**: Pythonで binary FBX の Model ノードと Connection をパースし、正常/不良ファイルのノード階層を比較 → 不良側にのみ余分なラッパーノード(FBX内の名前は `Corgi`)を発見
3. **全ファイルの走査**: 同じラッパーを持つFBXを全件スキャン → 323個中195個が該当と判明
4. **Unity内での実パス確認(決め手)**: `AnimationUtility.GetCurveBindings` でインポート後の実際のカーブパスをダンプ → 生FBXのノード名 `Corgi` はインポート後 `Corgi@Skin` になっており、除去すべきプレフィックスは `Corgi@Skin/` だと確定
   - ※最初は生FBXのノード名から `Corgi/` と推定して空振りした。**生FBXのノード名とUnityインポート後のパスは一致しないことがある**ので、パス修正系は必ず実パスをダンプしてから行うこと
5. Unityがプロジェクトを開いたまま(batchmode不可)だったため、`[DidReloadScripts]` + マーカーファイル + `osascript` でのUnityアクティブ化により、Editorスクリプトを自動実行させる方式で作業した

## 修正内容

`Assets/Editor/CorgiAnimPathFixer.cs`(Unityメニュー **Tools > Corgi** に登録済み)で以下を実行:

1. **修正版クリップの生成**: 不良195個のFBXからクリップを `.anim` として複製し、`Assets/Dog_WelshCorgi/Ani_Fixed/` に保存
   - 各カーブパスの先頭 `Corgi@Skin/` を除去(例: 002は686カーブを書き換え)
   - 存在しない `Corgi@Skin` ノード自体に乗っていた回転カーブ(4本/クリップ、計772本)は、正常クリップと同じ構造になるよう除去
   - フレームレート・ループ等のクリップ設定とアニメーションイベントも元クリップからコピー(ループ設定が元のFBXインポート設定と一致することを確認済み)
2. **Animator Controller の参照差し替え**(計196箇所):
   - `New_Corgi.controller`: 2箇所
   - `WelshCorgi_1.controller`: 57箇所
   - `WelshCorgi_2.controller`: 81箇所
   - `WelshCorgi_3.controller`: 56箇所
3. **リネーム**: 元クリップと区別できるよう、修正版195個すべてを `_Fixed` サフィックス付きにリネーム(例: `002_Ball_Jump_Fixed`)。`AssetDatabase.RenameAsset` によるGUID維持リネームのため参照は無傷
4. **動作確認**: 002・003 が実機で再生されることを確認済み ✅

FBXファイル自体は一切変更していない。Controller のステート名も元のままなので、`animator.Play("002_Ball_Jump")` のようなステート名参照のコードは修正不要。
